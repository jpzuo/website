### 进程篇（事件循环）
浏览器的渲染进程负责这页面的渲染，也就是将 HTML、CSS 和 JavaScript 转换为用户可以与之交互的网页。默认情况下，**浏览器会为每个 Tab 标签创建一个渲染进程**。出于安全考虑，渲染进程都是运行在沙箱模式下。

事件循环有着很多队列，微队列、计时器队列、网络请求队列、事件队列、用户交互队列等。其中 **W3C 规定微队列优先级最高**，其他队列优先级由浏览器自行决定，但是一般来说用户交互队列优先级仅低于微队列。不同类型的任务需要存入不同队列中。

事件循环是浏览器的一个很重要的概念，它主要是用来协调浏览器各个线程之间的工作，使得页面能够正常工作。它会不断循环，每次循环都从任务队列中取出第一个任务，执行任务，直到任务队列清空它会进入休眠，之后如果有任务进入，它会被唤醒。

### 为什么要搞懂事件循环？
1. 只有搞懂了事件循环的本质才可以知道那些逻辑先执行那些后执行。比如: `Promise.resolve().then(() => {})` 和 `setTimeout(() => {}, 0)` 两个任务谁先执行。为什么 `Promise` 会先执行，而 `setTimeout` 会后执行。因为 `Promise` 是微任务，而 `setTimeout` 是宏任务。微任务优先级高于宏任务。
```js
setTimeout(() => {
  console.log(1)
}, 0)
Promise.resolve().then(() => {
  console.log(2)
})
console.log(3)

// 输出3 2 1
```2. 只有搞懂了本质才知道原来`setTimeout回调函数`延时执行的时间不一定是你指定的时间，它取决于优先级更高的任务队列中是否有其他任务，如果有其他任务，那么 `setTimeout回调函数` 会等待其他任务执行完之后再执行，如果没有其他任务，那么 `setTimeout回调函数` 会立即执行。

```js
setTimeout(() => {
  console.log(1)
}, 1000)

// 延时方法
function sleep(duration) {
  // 指定时间后执行
  const start = Date.now()
  while (Date.now() - start < duration) { }
}

sleep(2000)

// 两秒后，输出1。为什么不是三秒？因为sleep方法内的死循环不会阻塞setTimeout定时器倒计时，且setTimeout的时间小于sleep的时间，所以在sleep方法执行完之后，setTimeout回调函数会立即执行。
```3. 才能更快更好排查页面卡顿原因，比如：一段很复杂的逻辑太过耗时导致页面卡顿，页面进入了死循环导致页面卡顿等等。

4. 当然我们也可以利用这些特性做一些操作，比如必须在页面重绘后执行某些操作，那么我们就可以利用 `setTimeout(() => {}, 0)` 延时执行，因为 `setTimeout` 优先级较低，会等待页面重绘之后再执行。当然在一些框架中有更好的实现方案，比如 `Vue` 中的 `nextTick` 方法。

### 渲染篇
浏览器渲染页面的过程主要分为以下几个步骤：解析 HTML 生成 DOM 树、解析 CSS 生成 CSSOM 树、将 DOM 树和 CSSOM 树合并生成渲染树、布局渲染树、绘制渲染树。我们都知道解析 CSS 不会阻塞 DOM 树的解析，但是解析 JS 会阻塞 DOM 树的解析。

![浏览器渲染流程图](https://blog.iszuo.com/pics/websit/xuanranliucheng.jpg)



**那么为什么解析 JS 会阻塞 DOM 树的解析呢？** 因为 JS 可能会修改 DOM 树，所以浏览器为了防止渲染出现不可预期的结果，所以会阻塞 DOM 树的解析。如果确定该 JS 文件不会修改 DOM 树可以设置`<script defer>` 和 `<script async>`。
